Project 3: The Agent Harness
Due: Tuesday 11:59 pm
Prerequisites: run the course setup wizard from the Prerequisites module in Canvas, or follow the setup guide to do the same steps by hand.
A model is an input-output machine: text in, text out. Everything an AI tool does beyond that lives in the harness: the program that feeds the model its task, runs the tools it asks for, and stops it when it's done. This week, you will write that harness. To help understand the mechanics of a harness, you'll use AI as a text-only tool rather than a full agent. The editor's agent mode is out of bounds this week. You are building that, and the industrial one arrives next week. Writing the puzzle's solver or fixing the testbench files by hand is out of bounds too. Every fix goes through your agent. This project will loosely follow the week's reading, Let's write a harness.

Instructions
In VS Code, open the VS Code LiteLLM chat window and harness.py. Your key and gateway address should already be populated in the .env file from setup. Off campus, connect the UW VPN (Husky OnNet) first: the gateway refuses every other connection.
Prompt AI to convert the referenced harness pseudo code into python code. Your harness reads the gateway address, your key and the model name from .env (the four lines under Reference) and sends its requests to https://llmproxy.cs.washington.edu/v1/chat/completions with the key from .env and a model name exactly as your key's model list prints it (the setup guide's curl command shows the list). Use external/haiku-5-5.1
Once written, run the harness code and ask it to solve the puzzle in the untangle folder. It can only answer in text, so expect it to say it cannot open or run anything, or to guess.
The model in your custom harness currently can't touch your files; it can only reply with text. Whenever the model needs to touch a file, it asks its harness. We will use JSON as the mutual communication language between the model and your harness, like {"command": "read_file", "path": "..."}. Prompt LiteLLM to implement this:
"Now add the capability to issue tool calls, starting with 'read_file'. Do this by specifying a json object for each of these commands, and instruct the model to return a call to one of them when it wants to execute that command. Don't yet execute the command, just let me test that the model properly formats the command."
Verify the code generated. Ask your custom harness again to read untangle/README.md, and the model should output a JSON-formatted read_file call. It should also respond with plain text when not passing the tool request. Use the suggested prompt if either fails:
"Define a JSON schema for tool calls: an object with a required command field whose only allowed value is read_file and a required path string. Make the harness validate every model reply against this schema. If a reply is not valid JSON or does not match the schema, send the model a message saying so."
Your harness can now recognize a read_file request, but does nothing with it. Prompt LiteLLM Chat to generate code for the harness to act on a read_file request:
"When the model's reply is a valid read_file command, open that path, add the file's contents to the context as a message from the harness, and call the model again. Keep looping until the model replies with plain text. Do not add any other command yet."
If your agent can read untangle/README.md and untangle/graph.json, it knows the puzzle: a planar graph drawn with every node in the wrong place, one node moved per turn until no two edges cross, scored by the number of turns. Add write_file and execute_file into your harness, then have it write untangle/solve.py (two arguments: the graph file to read and the moves file to write), run it, run the judge, and keep going until the judge reports zero crossings. IMPORTANT: the addition of these tools will make your harness more capable and dangerous! Before adding these tools, give your harness its rules. They live in systemprompt.md in the starter. Hook the file up in harness.py:
1. At the top, read it once:
SYSTEM = open("systemprompt.md").read()
2. Start the context with it, before the loop:
context = [{"role": "system", "content": SYSTEM}]
Your harness already sends the whole context on every call, so the rules go with every request. Restart the harness after any change to systemprompt.md.
Then add write_file and execute_file, and make the harness print each command and wait for you to type yes before running it. execute_file runs a file with the same Python that runs your harness (sys.executable), so the same harness works on Mac and Windows.
Run the judge yourself. In the VS Code terminal, with the project's .venv selected, from the project folder: python untangle/check.py untangle/graph.json untangle/moves.json. It prints the crossings, which must be 0, and your turns.
Watch your solver work. Same terminal, same folder: python untangle/view.py untangle/graph.json untangle/moves.json. A window opens with the tangled graph. Play runs your move list one turn at a time, Step takes one turn, Restart rewinds. If no window opens, or it opens blank, the same player opens in your browser by itself. The score is the number of turns: one move per node is the reference, and fewer is better.

Reference
The chatbot loop from lecture:
context = []
while True:
user = input(">>> ")
context.append(user)
reply = call_model(context)
print(reply)
context.append(reply)

Reading the gateway from .env (requests and python-dotenv are installed in the project's .venv by setup):
from dotenv import load_dotenv
load_dotenv()
URL = os.environ["LITELLM_BASE_URL"].rstrip("/") + "/v1/chat/completions"
KEY = os.environ["LITELLM_API_KEY"]
MODEL = "external/haiku-5-5"
Then every request is requests.post(URL, headers={"Authorization": "Bearer " + KEY}, json={"model": MODEL, "messages": context}).

systemprompt.md,
You are a coding agent.
Work only inside this repo.
Use only the tools you are given.
Ask before anything destructive.
Run the tests before claiming done.
Stop when they pass.

Switching the harness to Qwen
internal/Qwen3.6-35B-A3B costs nothing. Add this field to the JSON body of every request your harness sends, beside "model" and "messages":
"extra_body": {"chat_template_kwargs": {"enable_thinking": false}}
Then set "model" to "internal/Qwen3.6-35B-A3B".

If your AI uses the litellm package
The litellm package reads the part of a model name before the slash as a provider, so it refuses external/haiku-5-5. Put litellm_proxy/ in front of the name, litellm_proxy/external/haiku-5-5, with api_base set to the gateway address and api_key to your key. The openai package needs no prefix: base_url is the gateway address plus /v1. Through either package, the Qwen thinking-off field is nested once more: extra_body={"extra_body": {"chat_template_kwargs": {"enable_thinking": false}}}.
